# Stage 11 Specification: Certificate C1 Generation

## Overview

Stage 11 defines the architecture, evidence chain, JSON schema, canonical serialization, self-consistency validation, and empirical claim boundary for **Certificate C1** in the `quantum-compiler` pipeline.

The purpose of Certificate C1 is to transform the empirical execution and verification evidence generated by Stages 7–10 into a deterministic, auditable, and machine-readable certificate for the compiler's first transformation stage:
$$\text{AML} \longrightarrow \text{UTM}$$

---

## 1. Scientific Meaning of Certificate C1

Certificate C1 represents an authenticated record of:
1. **AML $\to$ UTM Translation** ($T: \text{AML-IR} \to \text{UTM-IR}$)
2. **Empirical Semantic Verification** ($\text{Sem}_{\text{AML}}(P, I) \equiv \text{Sem}_{\text{UTM}}(T(P), E(I))$) for a specific program execution instance.

> [!IMPORTANT]
> **CRITICAL SCIENTIFIC BOUNDARY:**  
> Certificate C1 is **NOT** a mathematical proof of the universal claim $\forall P \in \text{AML}, \text{Sem}_{\text{AML}}(P) = \text{Sem}_{\text{UTM}}(T(P))$.  
> The certificate explicitly includes `universal_claim = false` and `formal_proof = false` to guarantee that empirical test evidence is never confused with a universal mathematical theorem.

---

## 2. Evidence Chain Architecture

The certificate constructs a complete chain of evidence tracing from raw source code to verified observation parity:

```
    Source AML Program (Text)
               │
               ▼ SHA-256 Hash
        Source Identity
               │
               ▼ Stage 4 Parser
            AML-IR (Canonical Hash)
               │
               ▼ Stage 7 Translator
            UTM-IR (Canonical Metrics & Hash)
               │
               ▼ Stage 9 Dual Execution
     ┌─────────┴─────────┐
     ▼                   ▼
AML Interpreter     UTM Simulator
  (Sem_AML)           (Sem_UTM)
     │                   │
     ▼                   ▼
  Obs_AML             Obs_UTM
     └─────────┬─────────┘
               ▼ Stage 10 Semantic Verifier
      Verification Result (VERIFIED)
               │
               ▼ Stage 11 Certificate Generator
        Certificate C1 (JSON + SHA-256 Payload Hash)
```

## 4. Canonical Serialization & Hashing Algorithm

To ensure scientific reproducibility, Certificate C1 defines a deterministic canonical JSON serialization:
1. All JSON keys are recursively sorted alphabetically (`sort_keys=True`).
2. Indentation is set to 2 spaces with UTF-8 encoding.
3. Certificate SHA-256 hash is computed over the canonical JSON payload (with `certificate_hash` omitted or set to `None`).

Formula:
$$H_{\text{cert}} = \text{SHA-256}(\text{CanonicalJSON}(C1 \setminus \{\text{certificate\_hash}\}))$$

---

## 5. Self-Consistency Validation Rules

The function `validate_certificate_c1(certificate)` enforces 9 mandatory invariants:
1. **Required Fields:** All 12 top-level sections and mandatory fields exist.
2. **Valid Status:** Status must be one of `VERIFIED`, `NOT_VERIFIED`, `INVALID_TRANSLATION`, `EXECUTION_FAILURE`, `RESOURCE_LIMIT`, `ERROR`.
3. **Valid Hash Formats:** SHA-256 hashes must be valid 64-character hex strings.
4. **Valid UTM Identity:** `state_count > 0` and `transition_count > 0`.
5. **Consistency of `VERIFIED` Status:** `status == "VERIFIED"` if and only if `verified == true`.
6. **Strict Verification Invariants for `verified == true`:**
   - `source_halted == true`
   - `target_halted == true`
   - `observation_equal == true`
   - `halting_equal == true`
   - `mismatch_reason is None`
7. **Strict Formal Boundaries:** `universal_claim == false` and `formal_proof == false`.
8. **Scope Boundary:** `verification_scope == "SINGLE_EXECUTION_INSTANCE"`.
9. **Complexity Consistency:** `expansion_ratio == utm_steps / max(aml_steps, 1)`.

If any rule is violated, `validate_certificate_c1` returns `(False, "Error message")`.

## 6. Certificate Storage Location

Generated certificates are stored deterministically under:
```
certificates/C1_<source_program_hash>.json
```
This guarantees an auditable, persistent repository of verification certificates.
